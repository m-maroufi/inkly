# ⚠️ مدیریت و ساختار خطاها (Error Handling)

در اینکلی، تمام استثناها و خطاها توسط یک میدل‌ویر متمرکز پردازش شده و با کدهای وضعیت استاندارد HTTP و توضیحات شفاف بازگردانده می‌شوند.

---

## 📊 کدهای وضعیت مرسوم (HTTP Status Codes)

| کد وضعیت | عنوان                 | علت وقوع                                                                         |
| -------- | --------------------- | -------------------------------------------------------------------------------- |
| `200`    | OK                    | عملیات با موفقیت انجام شد و داده بازگردانده شد.                                  |
| `201`    | Created               | منبع جدید (پست، کامنت، رسانه، گزارش و...) با موفقیت در سیستم ثبت گردید.          |
| `400`    | Bad Request           | اعتبارسنجی پارامترها با اسکیما شکست خورده است یا فیلدهای ارسالی ناقص هستند.      |
| `401`    | Unauthorized          | کاربر لاگین نکرده، توکن منقضی شده یا دستکاری شده است.                            |
| `403`    | Forbidden             | کاربر لاگین کرده اما دسترسی یا نقش لازم (مثل دسترسی ادمین) را ندارد.             |
| `404`    | Not Found             | منبع مورد نظر (مقاله، کامنت، کاربر یا رسانه) با این شناسه یافت نشد.              |
| `409`    | Conflict              | تضاد اطلاعاتی (مانند ایمیل تکراری، اسلاگ تکراری یا تلاش برای گزارش پروفایل خود). |
| `500`    | Internal Server Error | خطای غیرمنتظره در سرور یا قطعی در اتصال دیتابیس/ردیس.                            |

---

## 🧩 نمونه پاسخ خطای اعتبارسنجی (`400 Bad Request`)

زمانی که ورودی با اسکیماهای Zod همخوانی نداشته باشد:

```json
{
  "success": false,
  "message": "Validation failed",
  "errors": [
    {
      "field": "title",
      "message": "Title must be at least 3 characters long."
    },
    {
      "field": "categoryId",
      "message": "Invalid category ID."
    }
  ]
}
```

## 🚫 نمونه پاسخ خطای عدم دسترسی (`403 Forbidden`)

```json
{
  "success": false,
  "message": "You are not authorized to perform this action."
}
```
